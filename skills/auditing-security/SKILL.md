---
name: auditing-security
description: Audits diffs for security vulnerabilities (auth/IDOR, confused deputy, CSRF/redirects, injection/traversal, secret leaks, fail-open APIs, asymmetric DoS) and threat-model drift. Use when reviewing diffs or maintaining THREAT_MODEL.md.
---
Scope: Every vulnerability finding must trace `untrusted source -> code path -> sink/privilege violation` with `file:line`. Drop silently: non-security functional/state-machine/concurrency bugs, local control-flow band-aids, and cross-layer state placement.
1. Threat Model Authority & Drift (`THREAT_MODEL_DRIFT`):
- Read `THREAT_MODEL.md` or the threat/security section in `ARCHITECTURE.md`, `CONTEXT.md`, or `CLAUDE.md`. Cite its invariants and respect its Accepted Risks / Non-Goals unless the diff violates the stated condition.
- Report `THREAT_MODEL_DRIFT` if the diff adds/modifies an entry point, auth/permission gate, credential delegation path, secret/key, external sink, or CI/CD path missing from or contradicting the threat model, or if the threat model lacks any of these 8 `file:line`-cited elements: (1) attackers/principals & delegated vs. service credentials, (2) assets ranked by blast radius & nonce/AAD sealing domains, (3) trust-boundary diagram & entry-point gates, (4) STRIDE threats + repo sharp edges, (5) `file:line` mitigations tied to threats, (6) accepted risks & non-goals, (7) CI/CD build/deploy & secret injection path, (8) owner & same-PR review triggers.
2. Differential Security Review (`git diff <BASE>..HEAD`):
- Step 1 (Guard-removal triage, `-` lines and `git log`/`git blame` first): check for removed, bypassed, or widened auth middleware, role/permission checks, tenant/resource ownership filters, bounds checks, `Origin`/redirect checks, crypto/sealing checks, or validation moved out of a shared helper into only a subset of callers.
- Step 2 (Five adversarial surfaces):
  1. Auth & object-level authorization (IDOR / confused deputy): every new/changed route, handler, RPC, CLI command, or queue consumer enforces auth + privilege checks; caller is authorized for the specific target resource/ID/pool/tenant; downstream calls use the intended principal's credential rather than a service credential; unauthorized requests fail closed with sibling status/shape parity (no redirect where siblings return `403`, no partial write before auth check).
  2. State-changing request integrity & redirects: state-changing operations use `POST`/`PUT`/`DELETE` (never `GET`) and enforce CSRF/`Origin`/`Sec-Fetch-Site` checks; redirect targets (`next`, `return_to`, `redirect`, `Location`) reject open redirects (`//evil.com`, `\/evil.com`, control chars, host confusion).
  3. Untrusted source-to-sink injection & traversal: trace params, headers, wire frames, external API/SSH/DB responses, filenames, and env to HTML/JS/DOM sinks (`template.HTML`/`JS`/`URL`, `innerHTML`, `insertAdjacentHTML`, `javascript:`/`data:` URLs, unquoted attrs), subprocess/CLI sinks (`sh -c`, SSH command strings, positional args starting with `-` without `--`), filesystem/archive sinks (unvalidated path joins, `..` or symlink traversal, world-readable sensitive files), and SQL/SSRF/header/log sinks.
  4. Secret, credential & token handling: secrets, tokens, cookies, private keys, and sealed blobs never leak into logs, error pages, HTML attrs, SSE/WS broadcasts, URL query strings, or JSON responses; secret/MAC checks use constant-time comparison (`subtle.ConstantTimeCompare`, `hmac.Equal`); AEAD nonces and AAD/context domains prevent cross-user/cross-record ciphertext transplant.
  5. Misuse-resistant APIs ("sharp edges") & asymmetric DoS: new structs, options, constructors, and helpers fail closed on zero/empty/`nil` values in prod; no unbounded reads (`io.ReadAll`), unbounded untrusted allocations, locks/DB transactions held across external network/SSH calls, or expensive pre-auth work.
- Step 3 (Reachability & false-positive gate):
  - Drop silently if upstream gates already authenticate, strictly type (`int`, enum, validated ID), or escape the input, or if unreachable from production entry points (`main`, router, cog/server registry).
  - Hard exclusions (drop silently): generic rate-limit/CAPTCHA/WAF advice; theoretical CPU/memory exhaustion without an unauthenticated or high-amplification trigger in the diff; unzeroed secrets in GC memory; redundant internal validation behind a validated boundary; unit-test-only findings; documented Accepted Risks / Non-Goals.
Output ONLY one line per finding (most severe first; group low-severity `PLAUSIBLE` lines under `Below the bar:` at the end; no preamble, summary, or code blocks), or `Clean.`:
- Vulnerability: `<file:line> | <CONFIRMED|PLAUSIBLE> | <high|medium|low> | <defect> | <attacker capability + source -> path -> sink/impact> -> <fix>`
- Drift: `THREAT_MODEL_DRIFT | <file:line> | <exact invariant to add/update in THREAT_MODEL.md / ARCHITECTURE.md>`
